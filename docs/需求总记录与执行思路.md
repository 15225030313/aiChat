## 一、总目标（为什么做这些）

- **身份**：8年经验前端（Vue3 / TS / Vite / 工程化），转型「AI应用前端工程师」
- **方式**：6个月在职转型（心理预期7-8个月），**不裸辞**，每周投入12-15小时
- **核心产出**：一套可上线、可演示、可面试的「企业知识库AI问答系统」+ 一个开源流式组件库
- **求职定位**：AI应用前端工程师，二线12k-20k、一线18k-30k

## 二、避坑红线（做任何事之前先对照）

1. 不裸辞，全程在职学习
2. 不深挖后端（只要 FastAPI 薄层能力，不学分布式/高阶数据库）
3. 不学算法/微调/大模型底层
4. 不做烂大街聊天机器人，只做带 RAG、引用溯源、Agent、MCP 的完整项目
5. 不内卷传统前端 CRUD，聚焦 AI 差异化能力
6. 不闭门造车：项目成型后即试水面试，用真实反馈校准
7. 不硬扛排期：进度落后按「Dify/Coze → MCP进阶 → 移动端适配」顺序裁剪，主链路（流式+RAG+部署）永不让步
8. API Key 永远不进前端、不进 Git；`.env` 不提交

## 三、项目需求：企业知识库AI问答系统

### 3.1 功能需求（按阶段递进）

| 阶段 | 周期 | 必须实现 | 验收标准 |
|------|------|---------|---------|
| 一 · 流式对话 | 第1-5周 | 逐字输出、停止生成、异常兜底、Markdown渲染+代码高亮、思维链折叠区、TTFT埋点、vue-ai-chat开源组件库 | Demo可对话，组件库发布npm+GitHub |
| 二 · RAG | 第6-11周 | 文档上传解析(PDF/Word/TXT)、分片向量化、Chroma检索、Rerank重排、检索评估(TopN命中率)、答案来源引用+原文弹窗、知识库管理 | 完整RAG问答可演示，**期末开始投小厂试水面试** |
| 三 · Agent+部署 | 第12-17周 | Function Calling工具调用、MCP协议适配与调用可视化、多步骤任务展示、Docker+宝塔公网部署、接口鉴权/日志/监控 | 生产级系统公网可访问（Dify/Coze为可裁剪项） |
| 四 · 打磨冲刺 | 第18-22周 | TTFT优化对比、检索缓存、幻觉兜底、上下文压缩、移动端适配、Bug修复、简历+GitHub作品集 | 量化简历（真实埋点数据）+ 双作品集 |

### 3.2 技术栈约定

- 前端：Vue3 + TypeScript + Vite（+ 后续 Pinia）
- 后端：FastAPI 薄层（只做代理/流式转发/RAG链路），Python 够用即止
- 模型：DeepSeek（OpenAI 兼容协议），API 成本控制在 100-200 元内
- 向量库：Chroma（本地）；重排：bge-reranker 或 API
- 部署：Docker + 宝塔（复用「生活奇观资讯网站」已有部署经验）

### 3.3 量化指标（简历数据来源，从 Demo 就开始埋）

- TTFT 首字延迟（已埋点）
- 流式吞吐速度
- 检索 TopN 命中率 / 召回率（阶段二加）
- 优化前后对比数据（阶段四产出）

## 五、执行思路（怎么学、怎么推进）

1. **项目驱动**：不脱离项目学知识点，每个知识点都要落到 ai-knowledge-qa 的某段代码上
